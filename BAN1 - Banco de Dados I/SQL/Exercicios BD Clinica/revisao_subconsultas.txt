REVISÃO ANY/ALL 
==================================
- Exemplos Práticos
   a) ANY:
      SELECT nome 
      FROM medicos 
      WHERE idade > ANY (
          SELECT idade 
          FROM pacientes
      )
      -- Retorna médicos mais velhos que pelo menos um paciente

   b) ALL:
      SELECT nome 
      FROM medicos 
      WHERE idade > ALL (
          SELECT idade 
          FROM pacientes
      )
      -- Retorna médicos mais velhos que todos os pacientes

- Dicas de Uso
   - Use ANY quando precisar de uma condição "pelo menos um"
   - Use ALL quando precisar de uma condição "todos"
   - Considere a performance com grandes conjuntos de dados
   - Verifique se a subconsulta retorna valores apropriados
   - Teste com diferentes conjuntos de dados 

REVISÃO DO OPERADOR EXISTS
============================

1. Sintaxe Básica
   - Uso: WHERE EXISTS (subconsulta)
   - Retorna TRUE se a subconsulta retornar pelo menos uma linha
   - Retorna FALSE se a subconsulta não retornar nenhuma linha
   - A subconsulta pode referenciar colunas da consulta externa

2. Exemplos Básicos
   a) Verificar existência:
      SELECT nome 
      FROM medicos m
      WHERE EXISTS (
          SELECT 1 
          FROM consultas c 
          WHERE c.codm = m.codm
      )
      -- Retorna médicos que têm pelo menos uma consulta

   b) Verificar não existência:
      SELECT nome 
      FROM medicos m
      WHERE NOT EXISTS (
          SELECT 1 
          FROM consultas c 
          WHERE c.codm = m.codm
      )
      -- Retorna médicos que não têm nenhuma consulta

3. Comparação com OUTROS Operadores
   - EXISTS vs IN:
     * EXISTS é geralmente mais eficiente
     * EXISTS pode usar índices melhor
     * EXISTS não precisa comparar valores específicos
   
   - EXISTS vs JOIN:
     * EXISTS é mais eficiente para verificar existência
     * JOIN pode retornar duplicatas
     * EXISTS é mais claro para verificações de existência

4. Casos de Uso Comuns
   - Verificar existência de registros relacionados
   - Encontrar registros sem correspondências
   - Verificar condições em tabelas relacionadas
   - Implementar lógica de "existe pelo menos um"
   - Implementar lógica de "não existe nenhum"

5. Boas Práticas
   - Use SELECT 1 na subconsulta (não precisa retornar dados)
   - Evite SELECT * na subconsulta
   - Use aliases para clareza
   - Considere a performance com grandes conjuntos de dados
   - Use NOT EXISTS para verificar não existência

6. Exemplos Práticos
   a) Médicos com pacientes:
      SELECT nome 
      FROM medicos m
      WHERE EXISTS (
          SELECT 1 
          FROM consultas c 
          JOIN pacientes p ON c.codp = p.codp
          WHERE c.codm = m.codm
      )

   b) Ambulatórios sem médicos:
      SELECT nroa 
      FROM ambulatorios a
      WHERE NOT EXISTS (
          SELECT 1 
          FROM medicos m 
          WHERE m.nroa = a.nroa
      )

7. Vantagens do EXISTS
   - Melhor performance que IN para grandes conjuntos
   - Mais eficiente que JOIN para verificações de existência
   - Pode usar índices efetivamente
   - Código mais limpo e legível
   - Mais flexível para condições complexas

8. Observações Importantes
   - A subconsulta deve ser correlacionada com a consulta externa
   - O resultado da subconsulta não importa, apenas sua existência
   - Pode ser combinado com outros operadores (AND, OR)
   - Útil para consultas aninhadas complexas
   - Bom para verificações de existência em múltiplas tabelas
